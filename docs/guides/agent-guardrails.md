# Agent Guardrails

`clrinf` enforces architectural boundaries deterministically whether an AI coding agent remembers your rules or not. Everything is driven from one source of truth: `clrinf.rules.toml`.

| Capability | CLI / MCP Tool | What it does |
|---|---|---|
| Brownfield onboarding | `clrinf init --guardrails [--ci]` | Scans your repo, creates `clrinf.rules.toml`, syncs agent rules, installs hooks, optionally writes CI workflow |
| Environment diagnostics | `clrinf doctor [--fix] [--json]` | Audits `clrinf.rules.toml`, agent sync, hooks, schema validity, `verify` status, and worker availability (`--fix` auto-remediates sync & hooks) |
| Live IDE diagnostics | `clrinf lsp` | Runs a pure-Rust LSP 3.17 stdio server publishing `verify` diagnostics on file open/save |
| Incremental verification | `clrinf hook install`, `clrinf verify` / `clrinf_verify` | Runs targeted checks after every agent edit and feeds violations back to the agent |
| Targeted change plan | `clrinf plan` / `clrinf_plan_change` | Handles mechanical schema/scaffold updates and hands the agent only the files and symbols to fill in |
| Single-source agent rules | `clrinf agents sync` | Writes the managed rule block into `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, and `.cursor/rules/clrinf.mdc` |
| Lean MCP surface | `clrinf mcp --profile lean` | Cuts fixed per-session MCP tool-schema token overhead |

## `clrinf.rules.toml`

```toml
[events]
schema_dir = "contracts/schemas"      # default: tools/clrinf-codegen/schemas

[events.services]                     # service name -> source root for drift checks
billing = "services/billing"
orders  = "services/orders"

[generated]
protect = true                        # block hand edits to files marked "Code generated by clrinf-codegen" (on --changed / hooks)

[[forbid]]                            # dependency rule: path prefixes + pattern
id      = "domain-no-infra"
scope   = "imports"                   # raw (default, comments stripped) | code (comments & strings stripped) | imports
paths   = ["services/orders/src/domain"]
pattern = "Infrastructure"
reason  = "Domain layers must remain free of infrastructure dependencies"
extensions = ["cs", "ts", "rs", "ex"] # optional

[[boundaries]]                        # modular monolith / service isolation
id      = "module-isolation"
modules = ["services/orders", "services/billing"]
public  = ["contracts", "Contracts", "public", "Public"]
reason  = "Cross-module imports must go through public contracts"

[agents]
extra = ["Implement only business logic inside handlers."]

[mcp]
profile = "lean"                      # full | events | lean
```

Unknown keys fail loudly so typos are never silently ignored.

## Setup Flow

```bash
clrinf init --guardrails --ci         # auto-detect layout + rules + agents sync + hooks + CI workflow
clrinf doctor --fix                   # check rules/sync/hooks/schemas/verify and auto-fix sync/hooks
# Or configure manually:
clrinf agents sync                    # generate agent instruction blocks (CI drift check: --check)
clrinf hook install --agent all       # Claude Code + Cursor + Antigravity + git pre-commit
clrinf verify                         # full repo check; --changed verifies only modified files
clrinf verify --format sarif --output clrinf.sarif  # SARIF 2.1.0 output for GitHub Code Scanning
clrinf lsp                            # start pure-Rust LSP stdio server for VS Code / Neovim / Zed
```

### Agent Hook Behavior
- **Claude Code:** Installed into `.claude/settings.json` (`PostToolUse`), preserving existing hooks. Violations exit with code `2` on `stderr` so Claude sees the diagnostic and self-corrects immediately; clean edits stay silent.
- **Cursor:** Installed into `.cursor/hooks.json` (`postToolUse`, `--format cursor`). Violations return exit code `0` with `{"additional_context": ...}` on `stdout` (`afterFileEdit` does not return context to the agent, so `postToolUse` is used).
- **Antigravity:** Installed into `.agents/hooks.json` (`PostToolUse`, `--format antigravity`) with the resolved absolute binary path; violations emit `{"decision":"block","reason":...}` on `stdout`.
  > **Verification note:** Claude Code and Cursor formats follow official specs. Antigravity's `.agents/hooks.json` schema is based on secondary references and should be verified in a live session; `git pre-commit` and CI `clrinf verify` remain the authoritative enforcement gates.
- **Git:** Installs `.git/hooks/pre-commit` running `clrinf verify --changed` (refuses to overwrite a non-clrinf hook without `--force`).

### What `clrinf verify` Checks
- Cross-service event topology (`TOPOLOGY_DEAD_EVENT`, `TOPOLOGY_ORPHAN_SUBSCRIBER`, `TOPOLOGY_UPCASTER_MISSING`).
- Code-vs-contract drift for `[events.services]` (`DRIFT_UNDECLARED_PUBLISH`, `DRIFT_UNDECLARED_SUBSCRIBE`, `DRIFT_RAW_OUTBOX_WRITE`, `DRIFT_UNKNOWN_ANNOTATED_EVENT`).
- `[[forbid]]` dependency rules (`RULE_FORBIDDEN_DEPENDENCY`).
- `[[boundaries]]` module isolation rules (`RULE_MODULE_BOUNDARY_VIOLATION`).
- Generated-file edit protection on `--changed` / hooks (`RULE_GENERATED_FILE_MODIFIED`, controlled by `[generated] protect = true`).

### Brownfield Event Annotations (Without Codegen Naming)
Existing repositories that do not use generated symbol names (`publishOrderPlaced`, `OrderPlacedHandler`) can declare event usage with a one-line comment in any language:

```rust
// @clrinf:publishes orders.placed.v1
```
```elixir
# @clrinf:handles billing.invoice.issued.v1
```

Both `clrinf topology drift` / `clrinf verify` and `clrinf topology impact` read these annotations (while ignoring string literals) to catch undeclared publishes/handlers, unknown event names (`DRIFT_UNKNOWN_ANNOTATED_EVENT`), and affected hand-written files.

### GitHub Code Scanning (SARIF 2.1.0)
```yaml
- uses: brkmustu/clrinf@v0.1.0
  with:
    sarif-file: clrinf.sarif
- uses: github/codeql-action/upload-sarif@v3
  if: always()
  with:
    sarif_file: clrinf.sarif
```

## Targeted Change Plan

```bash
clrinf plan orders.placed.v1 --service billing --role subscriber   # preview
clrinf plan orders.placed.v1 --service billing --role subscriber --apply
```

JSON output includes `schema_edit`, `fill_in` (per-language symbols and generated shell paths), `read_these` (hand-written files to inspect), `do_not_edit` (generated files), `constraints`, and `open_issues`.

## MCP Profiles & Resources

| Profile | Tools | Use case |
|---|---:|---|
| `full` (default) | 28 | All ecosystem, scaffold, and governance tools (`clrinf_doctor`, `clrinf_verify`, …) |
| `events` | 15 | Event-driven contract, topology, and `clrinf_doctor` tools |
| `lean` | 10 | Intent-level tools (`clrinf_plan_change`, `clrinf_verify`, `clrinf_crud_map`, `clrinf_crud_eject`, …) for smaller/local models |

Precedence: `--profile` > `CLRINF_MCP_PROFILE` > `clrinf.rules.toml` `[mcp]` > `full`. Calling a tool outside the active profile returns an explicit error.

**Read-only MCP Resources (`resources/list`, `resources/read`):**
- `clrinf://rules`: Active `clrinf.rules.toml` constraints.
- `clrinf://health`: Live JSON health report from `clrinf doctor`.
- `clrinf://topology`: Cross-service event topology ASCII graph and diagnostics.
